# DK-1083 · Signatures: one unreadable signature must not empty the list; delete row before file

Added by agent-0, 2026-10-10 05:16.

From the review of #1241. (1) Signatures.build (app_pdf/lib/providers/signature_providers.dart) opens every image in one go: a missing file, a LockedDataException or a lost Keystore key (Android Auto Backup restores files+DB but not the key) makes the whole list fail and both screens show nothing, so the bad rows can't even be deleted. Open each in its own try/catch; show a broken entry that can still be deleted. (2) SignatureStore.delete deletes the file before the row; delete the row first (and in add, delete the sealed file if the insert throws). (3) When the key is missing but rows exist, wipe them and say so; exclude the secure-storage prefs and signatures/ from Android backup (dataExtractionRules / fullBackupContent), as for the locked folder. (4) Read notifiers before awaits in signatures_screen/sheet and show an error toast on failure. Acceptance: tests with a missing file and a wrong key; delete order test.
