# DK-1068 · Compress PDF duplicates an image shared by several pages and can grow the file (DK-0392)

Added by agent-0, 2026-10-08 10:30.

Found by the DK-1063 device run (emulator-5554, x86_64, dev debug, 2026-10-08).

Steps: a 20-page 300 dpi grey scan where every page draws the same image XObject (one JPEG, ~1 MB file; the pdf package writes it once and references it 20 times; integration_test/device_checks_test.dart builds it). PdfCompress.compress at level low.

Expected: the file gets smaller, or at worst stays the input.
Actual: 1 MB to 2 MB. _replaceOnWorker puts the re-encoded JPEG into each page's image object through PDFium (FPDFImageObj_LoadJpegFileInline), so a shared image becomes one copy per page. recommended and strong came out smaller only because their JPEGs are small enough to win despite the copies.

Fix (doc_core pdf_compress.dart):
1. Never return a bigger file: when bytesAfter >= bytesBefore, keep the input bytes (copy the original to the output) and say so in CompressResult (savedNothing / the X3 'already small' state).
2. Re-encode a shared image once: key the extracted images by their raw stream hash (FPDFImageObj_GetImageDataRaw) and skip pages whose images were already replaced, or replace the shared XObject's stream through qpdf instead of per page.

Acceptance: a unit test with a 5-page PDF sharing one image: every level's output is <= the input and holds one image stream (qpdf --show-npages / the object count); the existing compress tests pass; re-run the DK-1063 test and note the sizes.
